# Paja documentation

`docs/` holds Paja's design and its operator-facing prose. The table below routes each topic to the one file that
owns it. Instructions for agents working on Paja's own code live in [`../CLAUDE.md`](../CLAUDE.md).

| File | When to read |
| --- | --- |
| [`quickstart.md`](./quickstart.md) | You want Paja to build your own project: install, set it up, write the first issue and land it |
| [`setup.md`](./setup.md) | You want to install Paja and start it, on Windows, Linux or macOS |
| [`safety.md`](./safety.md) | You are about to run Paja on your own machine and want to know what it can touch, how to limit it and how to undo it |
| [`troubleshooting.md`](./troubleshooting.md) | Paja printed an error, or you want to update or uninstall it |
| [`design/overview.md`](./design/overview.md) | You want to know what Paja is for and the principles every part follows |
| [`design/architecture.md`](./design/architecture.md) | You need the parts (Jono, Kaava, Posti, Mestari, Ahjo, Vasara, Paja Desk), what each does and how they connect |
| [`design/workflow.md`](./design/workflow.md) | You want to follow one piece of work from an issue to verified code on `main` |
| [`design/landing.md`](./design/landing.md) | You need to know who decides whether a change lands, the risk tiers, and when a person is asked |
| [`design/build-order.md`](./design/build-order.md) | You want to know what gets built next and the exit test for each step |
| [`design/decisions.md`](./design/decisions.md) | You need a settled decision (language, work source, where workers run, budget) and why |
| [`glossary.md`](./glossary.md) | You met a Finnish part name and want its meaning |
